3. Claude의 잘못▲ 맨 위

  • 조건을 쓸 수 없다고 잘못 말했다.
  • 규칙(대영이 쓰게 하는 것)을 어기고 완성 코드를 바로 준 적이 있다.
  • 값이 어디서 오는지 ← 화살표로 적어서 파이썬 문법처럼 보이게 했다.
  • main.py가 없는데 있는 것처럼 설명했다.
  • 길고 빽빽한 답으로 대영을 힘들게 했다.
  • 테스트를 건너뛰라고 한 적이 있다.
  • 2026-10-26 : 대영이 return 위치 에러를 고친 뒤에도, 먼저 한 설명 "with 안쪽이 아니라 with와 같은 줄"이 헷갈리게 쓰였다. 줄 번호와 칸 수로 다시 말했어야 했다.
  • 2026-10-26 : 대영의 return이 0칸으로 보인 화면을 보고 "저장할 때 줄 맞춤이 풀렸다"고 말했다. 근거가 없는 말이었고 책임을 돌리는 말이었다. 대영이 지적했다. 이후 칸 수로만 말한다.
  • 2026-10-26 : 뼈대의 테스트 주석이 읽기 어려웠다(대영이 이해하지 못함). 그래서 테스트 코드는 완성본을 주기로 했다.
  • 이전 대화를 읽었다고 하고 못 읽는다고 한 적이 있다. 대영이 지적했다.
  • 2026-10-26 : save_report 뼈대의 "글자를 하나씩 꺼내 … 적는다"가 헷갈리게 쓰여서, 대영이 make_report의 줄을 save_report 안에 복사했다. 같은 설명을 반복해서 대영이 이해하지 못했다. 실제 값(lines 안의 "이벤트 ID:EVT-001" 등)으로 따라가는 설명으로 바꿨다.

  • 2026-10-26 : 4번 조치 결과 4줄이 for 안에 있었는데 처음 지적 때 놓쳤다. 대영이 테스트에서 15줄(기대 16)이 나온 뒤 전체 코드를 보내서 찾았다. 현재 상태 줄만 고치라고 해서 한 번 더 걸렸다.

  • 2026-10-26 : "설명 기능을 찾아라"는 요청에 학습 설명 방식(learn)이 있어서 그 방식으로 바꿨다. 설명이 어려웠던 것은 맞다.
  • 6번 main.py 작업 중 : 설명을 문장으로 길게 써서 대영이 이해하지 못했다("이해불가", "말귀를 못 알아듣는다"). 대영이 원한 것은 이전 채팅처럼 코드 모양으로 보여 주는 설명이었다. 이후 코드 구조와 실제 값으로 한 줄씩 따라간다.
