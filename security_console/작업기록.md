# 보안 웹 콘솔 작업기록

작성일: 2026-10-27
기준 문서: `보안_웹콘솔_요구사항.md` (F1~F7, 2~6장, 7장의 정할 것 6가지)

---

## 1. 만든 것 한눈에

요구사항 문서의 기능을 전부 넣은 보안 웹 콘솔 1개를 만들고 실제로 서버를 띄워 56가지를 시험했습니다.

| 번호 | 요구 | 만든 곳(app.py) | 화면 주소 |
|---|---|---|---|
| F1 | 경고 목록, 점수 높은 순, 등급 색 구분 | `render_list` | `/` |
| F2 | 사건 상세, 근거 원본 로그, 같은 사용자의 다른 탐지 | `render_event`, `find_evidence` | `/event/사건번호` |
| F3 | 승인·거절·오탐 버튼, 누가 눌렀는지 기록 | `_approve`, `_reject`, `_false_positive` | 상세 화면 아래 |
| F4 | 승인 시 OCC에 조치 요청, 성공/실패 표시 | `call_occ` | 상세 화면 "조치 결과" |
| F5 | AI 보고서 만들기·보기·내려받기 | `build_draft`, `ai_polish` | `/event/사건번호/report` |
| F6 | 처리 이력 시간 순 | `render_history` | `/history` |
| F7 | 오탐 → 되돌리는 요청 + 오탐 기록 | `_false_positive`, `_do_revert` | 상세 화면 |

비기능(6장): 원본 로그 읽기만 / 관리자만 접속 + 일반 직원 칸 차단 / 승인·거절·조치 전부 로그 / 파이썬으로 동작 — 모두 반영했고 시험으로 확인했습니다. (파이썬 기본 기능만 사용, 설치할 것 없음)

## 2. 어떻게 만들었는지 (순서)

1. **요구사항 읽기** — 기능 7개, 받는 데이터 3종(탐지 결과·원본 로그·퇴사자 명단), 화면 4개, 7장의 "정해야 할 것" 6가지를 뽑았습니다.
2. **프로젝트에 있던 `detections.json` 확인** — 석연님 쪽 탐지 결과의 실제 모양(`event_id, detected_at, rule, event_type, user, src_ip, risk_score, priority, asset, impact_scope, evidence`)을 보고, `evidence`가 "원본 로그의 시각 목록"이라는 점을 확인했습니다. 시험 데이터도 이 모양에 맞췄습니다.
3. **7장의 6가지를 먼저 정함** (아래 3장). 정해야 코드가 나오기 때문입니다.
4. **뼈대 → 데이터 → 화면 → 조치 → 보고서 → 보안** 순서로 `app.py` 한 파일에 작성했습니다.
5. **시험 데이터 만들기** — `sample_data/` 에 탐지 결과 9건, 원본 로그 25줄, 퇴사자 명단.
6. **자동 시험(`test_console.py`) 작성 → 실행 → 실패한 것 고치기** (4장).
7. **README, 작업기록 작성 후 zip으로 묶기.**

왜 `app.py` 한 파일인가: 화면·DB·조치가 서로 얽혀 있어 나누면 파일 사이 이동이 늘고, 서버에 올릴 때 복사할 것이 많아집니다. 대신 파일 안을 번호 붙은 11개 구역으로 나누고 각 구역 위에 설명을 달았습니다.

## 3. 7장 "정해야 할 것" 6가지 — 내가 정한 것

팀과 다르게 정해졌으면 바꾸면 되는 **임시 결정**입니다.

1. **칸 이름 통일** → `event_id / detected_at / risk_score` 로 통일. 옛 이름 `id / time / score` 가 와도 받아서 바꿔 줍니다(`FIELD_ALIASES`). 시험으로 확인.
2. **퇴사자 접근의 event_type** → `RESIGNED_ACCESS` 를 새로 추가했습니다. 기존 6가지(ABNORMAL_LOGIN, OFFHOUR_LOGIN, UNAUTHORIZED_ACCESS, MALICIOUS_IP, TRAFFIC_SPIKE, CORRELATED_ATTACK)는 그대로입니다. **석연님과 이 이름으로 맞춰야 합니다.**
3. **로그 파일을 콘솔 서버로 가져오는 방법** → 콘솔은 "복사해 둔 파일을 읽기만" 합니다(`log_path`). 가져오는 쪽은 로그 서버에서 콘솔 서버로 주기적으로 복사하는 방식을 권장합니다(예: 1분마다 rsync). **복사 방법 자체는 만들지도 시험하지도 않았습니다.**
4. **탐지 코드를 합칠지** → **따로 두고 JSON만 받습니다.** 요구사항 1-1과 같은 방향입니다. 석연님이 만든 `detections.json` 을 `detections_path` 위치에 두면 됩니다.
5. **DB냐 파일이냐** → **SQLite**(파이썬 기본 내장, 설치 없음) + 감사 로그는 `data/audit.log` 파일에 한 줄씩. 사건 상태 변경이 한 번에 한 번만 일어나야 해서(두 번 눌러도 한 번만 승인) 파일보다 DB가 안전합니다.
6. **승인 후 OCC를 부르는 방법** → HTTP POST(JSON)로 `call_occ` 함수 하나에 모아 두었습니다. **OCC가 실제로 어떤 주소·모양을 받는지 모르기 때문에 요청 내용은 내가 가정한 것**입니다. 정해지면 이 함수만 고칩니다.

## 4. 만들면서 고친 것

시험을 돌려 나온 문제와 그 밖에 스스로 점검해서 고친 것입니다.

**고침 1 — 잘못된 보안 토큰을 보내면 403이 아니라 서버 오류(500)**
- 어디: `app.py` 의 `_route` 안 CSRF 확인 줄
- 증상: 한글이 섞인 가짜 토큰을 보내면 `hmac.compare_digest` 가 글자 비교에서 오류를 냈습니다.
- 고친 것: 두 값을 바이트로 바꿔서 비교.
- 왜 필요한가: CSRF 토큰은 "이 버튼이 이 화면에서 눌린 것이 맞다"를 확인하는 장치입니다. 잘못된 요청은 조용히 403으로 거부되고 감사 로그에 `csrf_reject` 로 남아야 합니다. 500이면 거부는 되어도 기록 방식이 달라지고 오류만 쌓입니다.

**고침 2 — AI 결과의 사실 검사가 느슨했던 것**
- 어디: `build_draft` 가 돌려주는 "반드시 남아야 하는 낱말 목록"
- 증상: 점수를 `"90"` 으로 검사하면, AI가 점수를 바꿔도 다른 숫자 안에 `90` 이 있으면 통과할 수 있었습니다.
- 고친 것: `"90점"` 처럼 단위까지 붙여 검사.
- 왜 필요한가: 요구사항 4장은 "점수·등급은 AI가 정하지 않는다"입니다. AI가 숫자를 바꿨는지를 코드가 잡아내야 이 규칙이 지켜집니다.

**시험 기대값 정정 (코드는 맞았음)** — 심각 등급 사건 수를 3건으로 적었는데 실제 데이터(90, 90, 95, 99점)로는 4건이 맞아서 시험을 고쳤습니다.

## 5. 시험 결과

`python3 test_console.py` → **56건 통과 / 0건 실패.**

확인한 것:
- 로그인 없이 접근 불가, 틀린 비밀번호 거부, 5번 틀리면 10분 잠금, 로그아웃 뒤 접근 불가
- 허용 대역 밖 접속은 로그인 화면도 안 보이고 403
- CSRF 토큰 없음/틀림 → 403, 상태가 안 바뀜
- 목록: 점수 높은 순, 등급 글자 4종, 등급 필터, 형식 오류 2건 건너뛰고 안내, `<script>` 가 든 값이 글자 그대로 보임
- 상세: 시각+사용자가 같은 근거 로그만 표시(다른 사용자 로그 안 섞임), 같은 사용자의 다른 탐지, 퇴사자 표시
- 승인 → 시험 모드 기록, 같은 사건 두 번 승인 불가, 허용 안 된 조치 이름 거부
- 거절 기록, 오탐 → unlock_account 되돌리기 요청 생성, 조치 전 오탐은 되돌리기 없음
- 처리 이력 5종 모두 표시
- 보고서 5개 구성, 사실 그대로, `.md` 내려받기
- 원본 로그 파일이 시험 전후로 **한 글자도 안 바뀜**(해시 비교)
- 감사 로그에 로그인 성공/실패/CSRF 거부/승인 기록이 있고 비밀번호는 없음
- 실제 모드(가짜 OCC 서버로): 성공 표시, OCC가 받은 내용, 토큰 전달, 실패 표시 → 다시 요청 → 성공, 되돌리기 실패 → 다시 요청 → 성공
- AI 정리 결과 검사: 가짜 응답으로 확인 — 정상은 통과, 점수 변경·새 IP 끼워넣기·제목 누락은 버리고 규칙 기반 초안 사용, 네트워크 실패도 초안 사용

## 6. 아직 안 해 봤거나 한계 (솔직하게)

- **브라우저로 화면을 눈으로 확인하지 못했습니다.** 서버가 돌려주는 HTML 내용과 동작은 시험했지만 실제 모양(색, 간격, 휴대폰 화면)은 직접 열어 보고 확인해야 합니다.
- **진짜 AI 호출은 못 해 봤습니다.** 키와 인터넷이 없어서 가짜 응답으로 "사실 검사 코드"만 시험했습니다. `ai_model` 이름과 API 호출은 첫 실행 때 확인이 필요하고, 실패하면 자동으로 규칙 기반 초안이 나옵니다.
- **OCC 요청 모양은 가정**입니다(3장 6번). 진짜 OCC와의 연동은 시험하지 못했습니다.
- **`evidence` 는 "원본 로그의 time 값 목록"이라고 가정**했습니다(프로젝트의 `detections.json` 이 그 모양). 다른 방식이면 `find_evidence` 를 고칩니다.
- **등급 기준 점수(심각 90, 높음 80, 주의 50)는 임시값**입니다. `classifier.py` 의 80/50과 맞춰 정했습니다. 팀 합의 후 `config.json` 의 `grade_thresholds` 만 바꾸면 됩니다.
- **"점수 이유"는 규칙·점수·근거 건수로 보여 줄 뿐**입니다. 탐지 결과에 `reason` 칸이 있으면 같이 보여 주도록 해 두었으니, 석연님께 요청해 볼 수 있습니다.
- 파이썬 3.13에서만 시험했습니다. 우분투 서버의 파이썬 버전은 확인하지 못했습니다.
- **HTTP 기본**입니다. 비밀번호가 암호화 없이 내부망을 지나가므로 인증서가 있으면 `tls_cert`, `tls_key` 를 채우세요(이 기능도 시험은 안 했습니다).
- 접속 차단은 앱 안에서도 하지만, **방화벽(pfSense)에서도 같이 막아야** 합니다. 앱이 보는 접속자 주소는 직접 연결된 쪽 주소라서, 앞에 프록시를 두면 프록시 주소로 보입니다.
- 로그인한 사람 목록(세션)은 메모리에 있어 서버를 다시 시작하면 모두 로그아웃됩니다.
- 이미 들어온 사건은 탐지 결과 파일이 바뀌어도 갱신하지 않습니다(처리 기록 보호). 점수를 다시 매겨야 하면 새 `event_id` 로 보내야 합니다.
- 원본 로그는 시각별로 메모리에 색인합니다. 파일이 아주 크면(수백 MB) 느려질 수 있습니다.

## 7. 팀에 물어볼 것

1. 석연님: 퇴사자 접근 유형 이름을 `RESIGNED_ACCESS` 로 써도 되는지, 탐지 결과에 `reason` 칸을 추가할 수 있는지, `evidence` 가 로그의 `time` 값 목록이 맞는지
2. OCC 담당: 계정 사용 중지(`lock_account`)를 받는 주소와 요청 모양, 인증 방법
3. 로그 서버 담당: `/var/log/astra/app.log` 를 콘솔 서버로 복사하는 방법과 주기
4. 방화벽 담당: 개발(VLAN 30)·인사(VLAN 40) 등에서 콘솔 서버 8080 포트 차단 규칙
5. 전체: 등급 기준 점수
